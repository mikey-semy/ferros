# M6g — Файловая система вширь (фаза 2b)

После модели процессов (M6f) расширяем ФС: запись на диск, запись/создание файлов на FAT,
подкаталоги, листинг каталогов и настоящий слой VFS. Цель — то, что нужно shell'у (M7): `ls`,
`cd`, `cat`, `echo > файл`, запуск программ из подкаталогов.

Этапы: **M6g1 — запись секторов virtio-blk** (готово), M6g2 — запись/создание файлов на FAT
+ `write(fd)`/`O_CREAT`, M6g3 — подкаталоги + `mkdir`, M6g4 — листинг (`getdents`), M6g5 —
слой VFS (трейт ФС + разрешение путей).

## 2026-06-28 — M6g1 (2b1): запись секторов на virtio-blk

Диск теперь можно не только читать, но и **писать** — фундамент под запись на FAT.

- **`write_sector(lba, &buf)`** — зеркало `read_sector`, тот же путь virtqueue, только данные
  едут память → устройство: заголовок `VIRTIO_BLK_T_OUT`, дескриптор данных БЕЗ
  `VIRTQ_DESC_F_WRITE` (устройство их только читает), узор копируется в bounce-буфер ДО
  постановки запроса.
- **Рефакторинг (без копипасты).** Общая часть запроса вынесена из `submit_read`:
  `setup_chain(blk_type, lba, data_device_write)` заполняет заголовок и цепочку из трёх
  дескрипторов, `run_request()` кладёт голову в avail-кольцо, пинает устройство, опрашивает
  used-кольцо и проверяет байт статуса. `submit_read` = setup(IN) + run + копирование
  устройство→вызывающий; `submit_write` = копирование вызывающий→буфер + setup(OUT) + run.
- **Тест `blk_write`** — НЕДЕСТРУКТИВНЫЙ: на секторе далеко за метаданными FS (LBA 100000 из
  131072) читаем оригинал → пишем узор (`i ^ 0xA5`) → читаем обратно → возвращаем оригинал;
  сверяем, что прочитанное равно записанному. Образ остаётся прежним для других тестов.
- **Проверка.** `cargo test` — 37 тестов зелёные; fmt/clippy чисто; загрузка headless чистая.

## 2026-06-28 — M6g2 (2b2): запись файлов на FAT32

ФС теперь умеет **создавать и перезаписывать файлы** в корневом каталоге — ядро может писать на
диск, а не только читать. Это ядро записи, на котором дальше встанут сисколлы (`write`/`O_CREAT`)
и подкаталоги.

- **`Fat32::write_file(name, data)`** (создаёт или перезаписывает файл):
  1. `locate_or_free_slot` — за один проход каталога находит либо существующую запись (под
     перезапись, с её первым кластером — чтобы освободить старую цепочку), либо первый свободный
     слот (`0xE5`/`0x00`) под создание. `-DirFull`, если свободного слота нет (расширение
     каталога — позже).
  2. При перезаписи `free_chain` возвращает кластеры старого содержимого в пул (запись FAT → 0).
  3. `alloc_chain(n)` выделяет `n = ⌈len/cluster⌉` свободных кластеров и связывает их;
     `alloc_cluster` сканирует FAT ПО СЕКТОРАМ (не по кластеру за раз), берёт первый с записью 0
     и метит его EOC. Пустой файл → первый кластер 0 (как в FAT).
  4. `write_chain` пишет данные по секторам, дополняя последний неполный сектор нулями.
  5. `write_dir_entry` — 32-байтная запись: имя 8.3, атрибут «архив», первый кластер (hi/lo),
     размер; поля времени/даты обнулены.
- **Запись FAT зеркалится во ВСЕ копии** (`num_fats`, обычно 2): `write_fat_entry` делает
  read-modify-write записи в каждой FAT, сохраняя 4 старших зарезервированных бита. Иначе вторая
  копия рассогласуется (наш читатель использует только первую, но сторонние инструменты — нет).
- **Тест `fat_write`** — на собственных файлах (`NEWFILE.TXT`, `BIGFILE.BIN`), не трогая
  `HELLO.TXT`/программу `HELLO`: создание+чтение; перезапись более коротким (старая цепочка
  освобождается, «хвоста» нет); многокластерный файл (20000 Б, узор `i^0x5A`) — чтение целиком.
  `fat_read` после этого по-прежнему читает `HELLO.TXT` — значит выделение кластеров не задело
  занятые.
- **Проверка.** `cargo test` — 40 тестов зелёные; fmt/clippy чисто; загрузка headless чистая.

## 2026-06-28 — M6g3 (2b3): запись файлов через сисколлы

Пользовательская программа теперь может **создать файл и записать в него** — `open(O_CREAT)` +
`write(fd)` + `close`. Это связывает запись на FAT (M6g2) с кольцом 3.

- **`open(path, flags, mode)`** теперь понимает режим доступа (`O_RDONLY`/`O_WRONLY`/`O_RDWR`),
  `O_CREAT` (создать пустым, если нет) и `O_TRUNC` (обрезать до нуля при открытии — сразу на
  диске). `mode` игнорируем. Дескриптор запоминает имя файла и флаг «открыт на запись».
- **`write(fd)` в обычный файл** (fd ≥ 3): диспетчер `sys_write` для fd, кроме 1/2 (консоль),
  уходит в файловый слой. Запись по модели **write-back**: байты из памяти пользователя
  (через `uaccess::with_user_bytes`) кладутся в буфер файла с текущей позиции (буфер при нужде
  расширяется), позиция сдвигается, файл метится «грязным». На диск ничего пока не идёт.
- **`close(fd)` сбрасывает на диск**: если файл «грязный» и открыт на запись — его буфер
  пишется обратно через `fs::write_file`. Дескриптор изымаем из таблицы ДО записи, чтобы не
  держать замок `PROCESSES` на время дискового ввода-вывода. Ошибка сброса → `-EIO`/`-ENOSPC`.
- **Программа `writetest`** + тест `write_syscall`: `open(O_CREAT|O_WRONLY|O_TRUNC)` → `write`
  строки → `close` (сброс) → повторный `open(O_RDONLY)` → `read` → сверка. Выход 0 при успехе,
  иначе отличимый код на каждом шаге. Файл `WRITTEN.TXT` — собственный (другие тесты не трогают).
- **Проверка.** `cargo test` — 41 тест зелёный; fmt/clippy чисто; загрузка headless: демо
  пишет файл из кольца 3 без паник.

## 2026-06-28 — M6g4 (2b4): подкаталоги + mkdir

ФС стала **иерархической**: пути вида `/a/b/file`, создание каталогов. Это нужно shell'у для
`cd`/путей и запуска программ из подкаталогов.

- **Разбор пути** (`resolve_parent`): делит путь на компоненты, спускается по промежуточным
  каталогам от корня (каждый обязан существовать и быть каталогом, иначе `-NotADirectory`),
  возвращает `(кластер каталога-родителя, имя последнего компонента)`. Обход одного каталога
  (`find_in_dir`/`locate_or_free_slot`) и так был cluster-generic — теперь просто стартует не с
  корня. `read_file`/`write_file` принимают полный путь (обратно совместимо: имя без `/` —
  файл в корне). `read_file` каталога → `-IsADirectory`.
- **`mkdir(path)`**: родитель должен существовать; выделяет кластер под новый каталог,
  инициализирует его записями `.` (на себя) и `..` (на родителя; 0, если родитель — корень,
  как требует спека FAT), затем пишет запись-каталог (`ATTR_DIRECTORY`) в родителя.
  `-AlreadyExists`, если имя занято. Откат (освобождение кластера) при сбое инициализации/записи.
- **Рефакторинг записи каталога**: `fill_dir_entry` (заполняет 32-байтную запись в буфере)
  переиспользуется и `write_dir_entry` (read-modify-write сектора), и `init_dir_cluster`
  (строит первый сектор нового каталога с `.`/`..`). `write_dir_entry` теперь принимает атрибут
  (0x20 файл / 0x10 каталог); `DirEntry` несёт `is_dir`.
- **Тест `fat_subdir`** (на своих каталогах): файл в подкаталоге (`SUBDIR/SUB.TXT`); вложенность
  в два уровня (`SUBDIR/INNER/DEEP.TXT` — двойной спуск); спуск через файл (`HELLO.TXT/x`)
  отвергается. `mkdir` идемпотентен для повторных прогонов (принимаем `AlreadyExists`).
- **Проверка.** `cargo test` — 44 теста зелёные; fmt/clippy чисто; загрузка headless чистая.

## 2026-06-28 — M6g5 (2b5): листинг каталога (getdents64)

Каталог можно **перечислить** из кольца 3 — основа для `ls`. Последний пользовательский кусок
ФС, нужный shell'у (`cd`/`ls`/`cat`/`echo >`/запуск — всё есть).

- **`open` различает файл и каталог** через `fs::lookup(path)` → `Node::File(содержимое)` или
  `Node::Dir(листинг)` за один проход (корень `/` — особый случай). Дескриптор каталога несёт
  флаг `is_dir`; `read`/`write` на нём — `-EISDIR`; на запись каталог не открыть (`-EISDIR`).
- **`getdents64(fd, buf, count)`**: записи каталога сериализуются в поток структур
  `linux_dirent64` (`d_ino`/`d_off`/`d_reclen`/`d_type` + нуль-терминированное имя, выравнивание
  8) ещё при `open` и кладутся в буфер дескриптора; сам вызов копирует столько ЦЕЛЫХ записей,
  сколько влезает в `count`, и двигает курсор. 0 — записи кончились; `-EINVAL`, если буфер
  меньше одной записи.
- **Листинг FAT** (`Fat32::list_dir` + `name_83_to_string`): обходит цепочку кластеров каталога,
  восстанавливает имена из формы 8.3 (`HELLO   TXT` → `HELLO.TXT`), отдаёт имя + признак
  каталога. Чтение файла отрефакторено в общий `read_entry` (его делят `read_file` и `lookup`).
- **Программа `lstest`** + тест `getdents`: открывает корень, читает записи через `getdents64`,
  идёт по ним по `d_reclen`, ищет `HELLO.TXT` (его кладёт build.rs) → выход 0.
- **Проверка.** `cargo test` — 45 тестов зелёные; fmt/clippy чисто; загрузка headless чистая.
