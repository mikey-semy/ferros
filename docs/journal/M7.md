# M7 — init + shell

Прероки готовы (M6): fork/execve/wait4/kill/signals + иерархическая FAT с чтением/записью,
подкаталогами, `mkdir` и листингом (`getdents64`). M7 доводит дело до **интерактивной системы**:
загрузка приземляется в shell, из которого человек запускает программы.

## Разбивка (PR на этап)

Решения по форме (зафиксированы с автором на старте M7):

- **Утилиты — внешние ELF** (`ls`/`cat`/`echo` — отдельные программы в `/bin`, shell их
  `fork`+`execve`), а не встроенные команды. Это упражняет fork/exec/wait и совпадает с
  ABI-«севером» (D8: цель — гонять настоящие программы). Значит **argv** нужен рано.
- **cwd — в ядре** (`chdir`/`getcwd` + относительный резолвинг путей, наследуется через
  fork/exec), а не отслеживается shell'ом в userspace. «Правильно» по POSIX, отдельный этап.

| Этап | Суть | Наблюдаемо |
|------|------|-----------|
| **M7a** | stdin/консоль: линейная дисциплина + блокирующий `read(0)` | программа читает строку с клавиатуры |
| **M7b** | argv/envp на стеке (`execve`+`spawn_user`) | программа печатает свои `argv` |
| **M7c** | cwd в ядре: `chdir`/`getcwd` + относительные пути | `cd`/относительный `open` работают |
| **M7d** | init (PID 1) + чистая загрузка (убрать демо-спам, реапинг сирот) | загрузка приземляется в запущенную программу |
| **M7e** | shell (REPL): разбор argv, fork→execve→wait4, builtins `cd`/`exit`, `$?` | интерактивный prompt |
| **M7f** | coreutils в `/bin` (`ls`/`cat`/`echo`/`mkdir`/`pwd`) | `ls /`, `cat /HELLO.TXT` |

Редиректы (`>`/`<`) и пайпы (нужны `dup2`/`pipe`) — опционально, после M7f.

## 2026-06-28 — M7a: stdin / линейная дисциплина консоли

`read(0)` теперь доставляет ввод с клавиатуры в кольцо 3 — первый кирпич под интерактив. До
этого `read(0)` уходил в таблицу файлов и возвращал `-EBADF`, а keyboard-задача просто печатала
символы; пути «клавиатура → программа» не было.

- **Линейная дисциплина** (`drivers/console.rs`) — «канонический» режим терминала: ввод копится
  построчно в редактируемой строке, **Enter** (`\n`/`\r`) завершает её (байты с `\n` уезжают в
  очередь готового, заблокированные читатели будятся), **Backspace** стирает последний символ (и
  на экране), всё набранное отражается на экран (echo). Так `read(0)` отдаёт причёсанные строки,
  а редактирование делает ядро.
- **keyboard-задача** (`process_input`, бывш. `print_keypresses`) больше не печатает сама, а
  кормит символами `console::feed_char`. Спец-клавиши (`RawKey`) пока игнорируем.
- **Блокирующий `read(0)`** (`files::read_stdin`): пусто — процесс метится `Blocked` и уступает
  CPU; завершённая строка будит его, он перечитывает буфер. Если `copy_to_user` падает (плохой
  буфер → `-EFAULT`), уже снятая строка возвращается в начало очереди (`console::unread`) — ввод
  не теряется, как `EFAULT` в Linux. Переиспользует блок/побудку
  планировщика (как `wait4`, M6f4): добавлены `block_current_on_stdin`/`wake_stdin_readers` и
  поле `blocked_on: BlockReason` у потока — чтобы будить ИМЕННО читателей stdin, а не родителей в
  `wait` (и наоборот). Блокирующий вызов корректен на собственном ядровом стеке процесса.
- **Развязка потерянной побудки**: проверку «ввод пуст?» и установку `Blocked` делаем в одной
  области с `IF=0` (на одном ядре между ними никто не вклинится), консольный буфер — всегда под
  `without_interrupts` (иначе спин-дедлок с вытеснением). Тот же приём, что у планировщика/VGA.
- **VGA**: добавлен `backspace()` (сдвиг курсора назад + затирание ячейки) — echo для
  редактирования строки.
- **Программа `stdintest`** + тест `stdin`: читает строку через `read(0)`, печатает обратно.
  Тест детерминирован — ДОЖИДАЕТСЯ блокировки читателя (счётчик `STDIN_BLOCKS`), затем программно
  подаёт `"hi\n"` в `feed_char` (имитируя клавиатуру), и проверяет, что прочитаны ровно эти 3
  байта (через `LAST_WRITE_LEN`/`LAST_WRITE_SUM`). Так проверяется весь путь «блок → побудка →
  доставка», а не только буфер.

## 2026-06-28 — M7b: argv/envp на стеке

`execve` теперь передаёт **аргументы** новому образу — без этого внешние утилиты (`cat FILE`,
`echo …`) не получили бы свои слова. До этого `execve` зануляла стек и игнорировала `argv`/`envp`.

- **Раскладка System V AMD64** (`build_user_stack` в `arch/x86_64/syscall.rs`): на вершине
  страницы стека строится начальный кадр — `[argc][argv0…][NULL][envp0…][NULL][auxv: AT_NULL]`,
  строки выше, всё выровнено так, что на входе в `_start` `rsp` указывает на `argc` и `rsp%16==0`
  (требование ABI). Пишем прямо по пользовательским VA, пока активно адресное пространство образа
  (как делает `elf::load`). Не влез в страницу → `E2BIG`.
- **`execve` читает argv/envp из СТАРОГО пространства** (`read_user_str_array`) ДО смены CR3:
  `NULL`-терминированный массив пользовательских указателей → владелые копии строк ядра (лимит
  `MAX_STR_ARRAY`, иначе `E2BIG`); затем раскладывает их на стек нового образа и ставит
  `regs.user_rsp` на `argc`. Регистры зануляем — аргументы программа берёт со стека.
- **`spawn_user`** строит пустой стек (`argc=0`) тем же `build_user_stack` — начальные процессы
  получают валидную единообразную раскладку (раньше `rsp` просто упирался в вершину страницы).
  Существующие программы её игнорируют и работают как прежде (регрессия — весь старый набор тестов).
- **Программы**: `argvecho` (на диске как `ARGVECHO`) — точка входа на ассемблере ловит `rsp` до
  пролога, передаёт в `argv_main`, тот сверяет argv; `execargv` (встроена) — `execve("ARGVECHO",
  ["ARGVECHO","ping","pong"], [])`. Тест `argv`: спавним `execargv`, ждём выхода, ожидаем код 0
  (argvecho увидел верные argv; 42 — execve упал, 10–13 — argv не те). Образ диска → v3.
- **Проверка.** `cargo test` — все тесты зелёные, новый `argv::execve_passes_argv_on_the_stack`;
  fmt/clippy чисто.

## 2026-06-28 — M7c: рабочий каталог (cwd) в ядре

У процесса теперь есть **текущий рабочий каталог**, и пути можно задавать относительно него —
основа для `cd` и относительных аргументов в shell. До этого все пути резолвились только от корня.

- **Per-process cwd** (`syscall/files.rs`): запись процесса в реестре `PROCESSES` (ключ — CR3)
  стала структурой `ProcState { fds, cwd }`. Благодаря этому cwd наследуется теми же хуками, что
  и дескрипторы: `fork` клонирует `ProcState` (cwd → ребёнку), `execve` переносит её (`rekey`,
  cwd переживает exec), `exit` убирает. Новый процесс стартует в `/`.
- **Относительный резолвинг** (`resolve_path`/`normalize`): путь без ведущего `/` достраивается от
  cwd, затем `.`/`..`/повторные `/` схлопываются (с зажимом на корне). FAT-слой `.`/`..` не
  понимает (имена сопоставляются как 8.3), поэтому разрешаем их ДО обращения к ФС. Резолвинг
  встроен в `sys_open` и в `execve` (путь exec — от cwd запускающего, ещё старого процесса).
- **`chdir(path)`** (80): резолвит путь, `lookup` обязан вернуть **каталог** (иначе `-ENOTDIR`/
  `-ENOENT`), затем сохраняет нормализованный абсолютный cwd. **`getcwd(buf, size)`** (79):
  копирует cwd с нулём, возвращает длину включая нуль (как сырой Linux), `-ERANGE` при малом
  буфере. Новый errno `ERANGE=34`.
- **Программа `cwdtest`** + тест `cwd`: `getcwd`==`/` → `chdir("SUB")` → `getcwd`==`/SUB` →
  относительный `open("INSIDE.TXT")` + чтение → `chdir("..")` → `getcwd`==`/`; код 0 при успехе,
  1–7 на конкретном шаге. На диск добавлены каталог `SUB` и `SUB/INSIDE.TXT` (образ → v4).
- **Проверка.** `cargo test` — все тесты зелёные, новый `cwd::cwd_chdir_getcwd_and_relative_paths`;
  fmt/clippy чисто.

## 2026-06-28 — M7d: init + интерактивный shell (M7d+M7e слиты)

Загрузка стала **интерактивной**: ядро приземляется в shell, из которого можно набирать команды и
запускать программы. По решению автора M7d (init) и M7e (shell) сделаны одним PR — init без shell'а
был бы пустым плейсхолдером, а вместе дают сразу «настоящий» наблюдаемый результат (prompt).

- **Чистая загрузка** (`main.rs`): убраны демо прежних милестоунов — потоки A/B (спам `A`/`B`),
  фиксированный список из 8 пользовательских процессов, M3/M4-демки (трансляции, пример маппинга,
  Box/Vec/String). Остался минимум: память → куча → драйверы (клавиатура, консоль, PCI, virtio-blk)
  → планировщик → один процесс **`shell` (PID 1)** → экзекьютор с задачей клавиатуры. Их роль
  (демонстрация подсистем) теперь несут интеграционные тесты в `tests/`.
- **Shell** (`user/hello/src/shell.rs`) — REPL без кучи: печатает `<cwd>$ `, читает строку со
  stdin, токенизирует на месте (пробелы → нули, массив указателей на слова), и:
  - встроенные `cd [dir]` (по умолчанию `/`), `pwd` (через `getcwd`), `exit [code]`;
  - иначе `fork` + `execve(argv[0], argv)` + `wait4` — внешняя программа с диска. Не нашлась —
    `command not found`, ребёнок выходит 127.
- **Каноническая консоль построчно** (`console::take_ready`): теперь `read(0)` отдаёт **одну строку
  за вызов** (до `\n` включительно), даже если в буфере уже несколько строк, — иначе shell получил
  бы все набранные команды одним `read`. (Для одной строки поведение прежнее, тест M7a цел.)
- **Тест `shell`**: «набираем» `ARGVECHO ping pong` + `exit 0`. ARGVECHO выходит 0 лишь при ровно
  этих трёх аргументах (иначе 10–13; провал execve — 127), поэтому `EXIT_CALLS==2` (ребёнок+shell),
  `EXIT_CODE_SUM==0` (оба вышли 0 → argv разобран и доставлен верно), `LAST_EXIT_CODE==0` (shell по
  `exit 0`). Ввод подаётся программно, как в тесте stdin.
- **Проверка.** `cargo test` — все тесты зелёные, новый `shell::shell_runs_a_command_with_args…`;
  загрузка под QEMU приземляется в `/$ ` и реагирует на ввод; fmt/clippy чисто.

## 2026-06-29 — M7f: coreutils в /bin (M7 завершён)

Система обзавелась **утилитами**: shell находит и запускает `echo`/`cat`/`ls`/`mkdir` из `/bin`.
Это закрывает M7 — у ferros есть интерактивная оболочка с набором базовых команд.

- **`sys_mkdir`** (83): единственный сисколл, которого не хватало утилитам, — `mkdir(path, mode)`
  (`mode` игнорируем) резолвит путь от cwd и зовёт `fs::mkdir`. Новый errno `EEXIST=17`
  (`FatError::AlreadyExists`). FAT-`mkdir` уже был с M6g4 — теперь доступен из кольца 3.
- **Поиск в `/bin`** (shell): команду без `/` shell ищет как `/bin/<cmd>` (PATH из одного
  каталога — `has_slash`/`build_bin_path`); путь с `/` исполняется как есть (ядро резолвит от cwd).
  Так `ls`/`cat` работают по голому имени из любого cwd, как в Linux.
- **Утилиты** (внешние ELF в `/bin`, точка входа на ассемблере ловит argv со стека):
  - `echo` — печатает аргументы через пробел;
  - `cat FILE...` — выводит файлы (open/read/write);
  - `ls [DIR]` — листинг каталога через `getdents64` (по умолчанию `.` = cwd);
  - `mkdir DIR...` — создаёт каталоги через новый сисколл.
- **Диск**: добавлен каталог `/BIN` с `ECHO`/`CAT`/`LS`/`MKDIR` (имена 8.3 заглавными, без LFN);
  образ → v5. Утилиты собираются как `[[bin]]`, но в ядро не встраиваются — только на диск.
- **Тесты**: `coreutils` («набираем» `echo hi`/`cat /HELLO.TXT`/`ls /` голыми именами →
  `EXIT_CALLS==4`, `EXIT_CODE_SUM==0`: все найдены в /bin и вышли с 0); `mkdir` (`mkdir /M7FBIN` →
  `fs::lookup("/M7FBIN")` == каталог — проверка по существованию, устойчива к повторным прогонам).
  Тест `shell` (M7d) переведён на путь `/ARGVECHO` (минуя /bin), а `argvecho` больше не проверяет
  `argv[0]` (это имя вызова — зависит от способа запуска).
- **Проверка.** `cargo test` — все тесты зелёные, новые `coreutils`/`mkdir`; загрузка под QEMU:
  `ls /`, `cat /HELLO.TXT`, `echo`, `mkdir`, `cd`/`pwd` работают из приглашения; fmt/clippy чисто.

## Итог M7

ferros загружается в интерактивный shell и умеет: ввод с клавиатуры (`read(0)`), запуск программ
с аргументами (`fork`/`execve` с argv + `wait4`), рабочий каталог (`cd`/`pwd`/относительные пути),
и набор утилит в `/bin`. Прероки для прикладного софта (M9, libc) на месте.

### Дальше (за пределами M7)
Редиректы (`>`/`<`) и пайпы (`|`) — нужны `dup2`/`pipe`. Затем M8 (сеть) или M9 (POSIX/libc по
ROADMAP). Также в бэклоге: настоящий `init` отдельно от shell (см. HARDENING), `rm`/`rmdir`,
LFN/длинные имена в FAT.
