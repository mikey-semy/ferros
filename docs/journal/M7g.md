# M7g — доделка shell (редиректы, пайпы, удаление)

M7 закрыл интерактивную систему (загрузка в shell + coreutils). M7g добавляет отложенные фичи
оболочки. Этапы: **M7g1 — редиректы `<`/`>`/`>>`** (готово), M7g2 — пайпы `|`, M7g3 — `rm`/`rmdir`.

## 2026-06-29 — M7g1: редиректы ввода/вывода

`echo hi > файл`, `cat < файл`, `ls > файл` теперь работают. Под капотом — обобщение модели
файловых дескрипторов и `dup2`.

- **Модель fd обобщена** (`syscall/files.rs`): раньше fd 0/1/2 были захардкожены в `read`/`write`
  (0→консоль, 1→VGA, 2→serial). Теперь это обычные записи таблицы с подложкой
  `Fd::{Console,Vga,Serial,File}`; `ProcState` по умолчанию заполняет 0/1/2 стандартными потоками.
  `read`/`write`/`lseek`/`getdents`/`close` диспетчеризуются по подложке, а не по номеру fd —
  поэтому stdin/stdout можно **перенаправить**. Вся диспетчеризация `write` переехала в файловый
  слой (раньше 1/2 обрабатывались в `syscall::dispatch`).
- **`dup2(oldfd, newfd)`** (33): направляет `newfd` на ту же подложку, что `oldfd`. Основа
  редиректа: открыть файл → `dup2(fd, 1)` → `write(1)` идёт в файл. Подложка копируется (не
  разделяется как Unix-«описание файла» — достаточно для open→dup2→close; см. HARDENING).
- **Сброс на `exit`** (`flush_current_process`): незакрытые грязные файлы (перенаправленный
  `> файл`, который программа не закрывает) пишутся на диск при завершении процесса — раньше
  сбрасывал только явный `close`. Делается **синхронно** в обработчике `exit`, пока процесс ещё жив
  (как `close`), а не лениво в reaper'е: иначе вывод не был бы durable к возврату родителя из
  `wait`, и следующая команда (`cat файл`) могла бы прочитать ещё не сброшенный файл. Аварийно
  завершённые (сигнал/сбой) процессы свой грязный буфер теряют — как в Unix.
- **`O_APPEND`** (для `>>`): позиция при открытии — в конце файла.
- **Shell** (`shell.rs`): `parse_redirects` вынимает из строки операторы `<`/`>`/`>>` и их цели
  (как отдельные слова — вокруг пробелы), остальное — команда с аргументами; в ребёнке перед
  `execve` — `apply_redirects` (open + `dup2` на 0/1). Встроенные команды редиректы пока
  игнорируют (MVP). `cat` без аргументов теперь читает stdin (нужно для `cat < файл`).
- **Тесты**: `redirect` — `cat < /HELLO.TXT > /M7GOUT.TXT`, проверяем, что `/M7GOUT.TXT` побайтово
  равен `/HELLO.TXT` (разом покрывает оба редиректа, `dup2`, модель подложек и сброс на exit);
  `append` — `echo a > f; echo b >> f` даёт `"a\nb\n"` (покрывает `>>`/`O_APPEND` и durability вывода
  между последовательными командами). Образ → v6 (нужен новый `/BIN/CAT`, читающий stdin).
- **Проверка.** `cargo test` — 52 теста зелёные (рефактор модели fd ничего не сломал); fmt/clippy
  чисто.

## 2026-06-29 — M7g2: пайпы `|`

`echo hi | cat`, `ls / | cat > файл` работают: вывод одной программы идёт на вход другой через
ядровый канал.

- **Объект-канал** (`syscall/files.rs`): `PipeBuf { data, readers, writers }` под
  `Arc<Mutex<…>>`, разделяемый концами и через fork. Подложки fd `Fd::PipeRead/PipeWrite` — это
  обёртки со счётом концов через **`Clone`/`Drop`**: `Clone` (fork/dup2) увеличивает счётчик,
  `Drop` (close/exit/kill) уменьшает и будит другой конец. Поэтому EOF/EPIPE работают при любом
  способе исчезновения конца, без ручного учёта на каждом сисколле.
- **`pipe(fds)`** (22): выдаёт `fds[0]` (чтение) и `fds[1]` (запись). **Блокирующее чтение**
  (`read_pipe`): есть данные — отдаём; пусто и писатели есть — блокируемся (`BlockReason::Pipe`,
  как stdin: замок буфера не держим через блокировку); пусто и писателей нет — EOF. **Запись**
  (`write_pipe`): дописывает (буфер неограничен — не блокирует) и будит читателей; `-EPIPE`, если
  читателей нет.
- **Закрытие fd на `exit` синхронно** (`release_current_process_fds`, бывш. `flush_current_process`):
  теперь не только сбрасывает грязные файлы, но и **дропает все дескрипторы** (концы канала →
  счётчик--→ EOF другому концу). Иначе читатель `cmd1 | cmd2` не увидел бы EOF, пока reaper не
  дойдёт до писателя — а в тесте reaper не крутится.
- **Shell** (`shell.rs`): `find_pipe` делит строку по первому `|`; `run_pipeline` создаёт канал,
  форкает два процесса (stdout левого → канал → stdin правого, каждый со своими редиректами через
  `exec_command`) и ждёт обоих. Родитель ОБЯЗАН закрыть оба конца, иначе правый не дождётся EOF.
  Поддержан один `|` (две команды).
- **Тест `pipe`**: `echo piped | cat > /SUB/M7GPIPE.TXT` → файл == `"piped\n"` (данные прошли через
  канал, cat увидел EOF после выхода echo). Файл в `/SUB`, чтобы не переполнять корень.
- **Проверка.** `cargo test` — 54 теста зелёные (рефактор read/write/exit ничего не сломал);
  fmt/clippy чисто.

## 2026-06-29 — M7g3: `rm`/`rmdir` (доделка shell завершена)

Файлы и пустые каталоги теперь можно удалять. Это закрывает «доделку shell» (редиректы + пайпы +
удаление).

- **Удаление в FAT** (`fs/fat.rs`): `unlink(path)` освобождает цепочку кластеров файла
  (`free_chain`, уже был с M6g2) и метит запись каталога удалённой (`clear_dir_entry`: первый байт
  → `0xE5`). `rmdir(path)` — то же для **пустого** каталога: `dir_is_empty` (только `.`/`..`) →
  иначе `NotEmpty`; затем освобождает его кластер. Адрес записи на диске даёт новый `locate_entry`
  (как `find_in_dir`, но возвращает `(сектор, смещение, DirEntry)`). Новый `FatError::NotEmpty`.
- **Сисколлы** `unlink`(87)/`rmdir`(84): резолвят путь от cwd (общий хелпер `path_arg`), зовут
  FAT-слой. `unlink` каталога → `-EISDIR` (для него `rmdir`); `rmdir` файла → `-ENOTDIR`; непустого
  каталога → новый errno `ENOTEMPTY=39`.
- **Утилиты** `/bin/rm`, `/bin/rmdir` (как остальные coreutils). Образ → v8.
- **Тест `rm`**: `echo x > f; rm f; mkdir d; rmdir d` — самоочищающаяся последовательность
  (создаёт и тут же удаляет, поэтому повторные прогоны не накапливают). Проверяет `EXIT_CODE_SUM==0`
  (rm/rmdir удалили СУЩЕСТВУЮЩИЕ цели) + `fs::lookup` (обоих больше нет).
- **Проверка.** `cargo test` — 55 тестов зелёные; fmt/clippy чисто.

## Итог M7g

Shell доведён: `<`/`>`/`>>` редиректы, `|` пайпы, `cd`/`pwd`/`exit` builtins, coreutils
(`echo`/`cat`/`ls`/`mkdir`/`rm`/`rmdir`) в `/bin`. Дальше — за пределами «доделки»: многоступенчатые
пайпы, ограниченный буфер канала + SIGPIPE, `stat`/`rename`, LFN.
