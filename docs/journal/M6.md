# Journal — M6: Storage + filesystem

> Диск выбран **virtio-blk** (а не ATA/AHCI) — современный, быстрый, чисто эмулируемый
> QEMU интерфейс из того же семейства, что и будущий virtio-net (M8). virtio — это
> PCI-устройство, поэтому первый шаг — **перечисление шины PCI**. Файловую систему читаем
> **своим кодом (FAT)** — как hand-rolled ELF-загрузчик (D9/D10): без зависимостей, полный
> контроль, teach-as-we-go. Разбивка: M6a PCI → M6b virtio-blk (чтение секторов) → M6c
> FAT-чтение → M6d VFS + файловые сисколлы. См. `docs/DECISIONS.md` D11.

## 2026-06-27 — M6a: перечисление шины PCI

Чтобы найти диск virtio-blk, ядру сперва нужно **увидеть, что висит на шине PCI**. M6a —
это фундамент: читаем конфигурационное пространство устройств и составляем их список.

- **Что такое PCI.** Шина, к которой подключены устройства; у каждого есть 256-байтная
  «анкета» — *конфигурационное пространство*: производитель, идентификатор, класс и адреса
  его регистров (BAR'ы). На x86 «механизм #1» читает её через два 32-битных порта:
  `0xCF8` (адрес: шина/слот/функция/смещение) и `0xCFC` (данные). Пишем координаты в один,
  читаем слово из другого.
- **`arch/x86_64/pci.rs`** (шов, CONVENTIONS §1): только механика портов —
  `config_read_u32` / `config_write_u32`. Пара «адрес→данные» обёрнута в `without_interrupts`,
  чтобы между ними никто не переписал 0xCF8 (атомарность). Весь сырой `unsafe` — здесь
  (D9). `config_write_u32` пока не используется — он понадобится в M6b (bus-master,
  настройка очереди virtio).
- **`drivers/pci.rs`** (переносимая часть): модель `PciDevice` (координаты + анкета + сырые
  BAR'ы), разбор `Bar` (I/O- против MMIO-, с учётом 64-битных BAR'ов через следующий),
  `enumerate()` (полный перебор 256 шин × 32 слота; функции 1..8 — только если устройство
  многофункциональное, бит `0x80` в header type), `find(vendor, device)` и `init()` —
  печать списка в serial. Портов здесь нет: шину обходим через арх-шов `arch::pci`.
- **Арх-нейтральный псевдоним.** В `arch/mod.rs` добавлен `pub use self::x86_64::pci;` (как
  для `context`/`USER_SPACE_END`), чтобы переносимый драйвер звал `crate::arch::pci`, не
  зная конкретной архитектуры.
- **Диск в QEMU.** В `Cargo.toml` (`test-args` + новый `run-args`) добавлен второй диск
  через контроллер virtio-blk: `-drive if=none,id=disk0,…` + `-device virtio-blk-pci`
  (отдельно от загрузочного диска, который bootimage даёт первым). Сам образ создаёт
  `build.rs`: raw `target/ferros-disk.img` 4 МиБ с сигнатурой `FERROSM6` в секторе 0
  (M6b прочитает и сверит). Подтверждено: bootimage 0.10.4 знает ключ `run-args`.
- **Тонкость с QEMU.** «Переходное» (transitional) устройство `virtio-blk-pci` по умолчанию
  отвечает на legacy-идентификатор `1af4:1001` и отдаёт legacy-регистры в **I/O-BAR0** —
  именно то, что нужно legacy-драйверу M6b (никакой `disable-modern` не понадобился).
- **Проверка.** `cargo test` — 16 тестов в QEMU зелёные (новый `pci_enumeration`: найден
  хост-мост `8086:1237`, найден virtio-blk `1af4:1001`, его BAR0 — непустой I/O-BAR);
  fmt/clippy чисто. Загрузка headless печатает 7 устройств на шине (хост-мост, ISA/IDE
  PIIX3 как многофункциональное `00:01.x`, ACPI, VGA, e1000, и `00:04.0 1af4:1001` —
  диск), паник нет.
