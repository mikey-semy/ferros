# Journal — M1: Kernel infrastructure

## 2026-06-26 — M1a: VGA writer + `print!`/`println!`

- Added `src/vga_buffer.rs`:
  - `Color` / `ColorCode` / `ScreenChar` describe the VGA cell format.
  - `Writer` tracks the column, writes to the bottom row and scrolls up (terminal-style).
  - All accesses go through `core::ptr::write_volatile` / `read_volatile` (memory-mapped
    I/O must not be optimized away).
  - Global `WRITER` behind `spin::Mutex` — `Mutex::new` is `const`, so a plain `static`,
    no `lazy_static` needed.
  - `core::fmt::Write` impl → free `{}` formatting; `print!` / `println!` macros.
- `src/main.rs`: `_start` now uses `println!` instead of the raw `0xb8000` loop.
- Dep added: `spin = "0.12"`.
- Behaviour note: output appears on the **bottom** row and scrolls up (like a terminal),
  unlike M0 which wrote to the top-left.
- Panic still just halts; a printing panic handler comes in **M1b** (via serial), to
  avoid the VGA-lock deadlock case.

### Next (M1b)
- Serial (COM1) output + `serial_print!` / `serial_println!`.
- A panic handler that prints the message.

## 2026-06-26 — M1b: serial (COM1) + printing panic

- Added `src/serial.rs`. Instead of the `uart_16550` crate (whose 0.6 API got heavy:
  `Result`, `Config`, `Uart16550Tty`, backends, a loopback self-test), we wrote our **own
  minimal 16550 driver** — a better lesson in talking to a peripheral chip:
  - `outb` / `inb` via inline asm (`out dx, al` / `in al, dx`) — x86 **port I/O**.
  - `SerialPort::init` runs the standard 16550 sequence (disable IRQs → set the 38400-baud
    divisor → 8N1 → enable FIFO → DTR/RTS/OUT2).
  - `send` waits for the LSR "transmit holding register empty" bit, then writes the data register.
  - `impl core::fmt::Write` → `serial_print!` / `serial_println!`; global `SERIAL1` behind
    `spin::LazyLock` (lazy init on first use; plain `Lazy` is deprecated → `LazyLock`).
- `_start` prints a line to COM1; the panic handler now prints to **both** VGA and serial.
- No new dependency (we dropped `uart_16550`).
- Verified: QEMU `-serial file:` captured `[serial] ferros COM1 online — debug channel ready`,
  and VGA still shows the two boot lines.
