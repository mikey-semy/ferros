# Journal — M4: Multitasking

## 2026-06-26 — M4a: кооперативные async/await-задачи (простой экзекьютор)

Первый шаг многозадачности — **кооперативные** задачи на `async`/`await`. Они
переключаются добровольно в точках `.await`; никаких прерываний и переключения
контекста (это фаза 2). Тут впервые «играет» куча из M3 — задачи живут в `Box`.

- `sched/mod.rs`: [`Task`] — обёртка над `Pin<Box<dyn Future<Output = ()>>>`. `Pin`,
  потому что future после старта нельзя двигать в памяти (может хранить self-ссылки).
- `sched/simple_executor.rs`: `SimpleExecutor` — FIFO-очередь задач; `run()` крутит
  её, опрашивая (`poll`) каждую задачу с «пустым» (dummy) waker'ом. `Ready` —
  выбрасываем, `Pending` — в конец очереди. Dummy-waker собран вручную через
  `RawWaker`/`RawWakerVTable` (все операции — no-op). Неэффективно (CPU не спит) —
  это осознанно, эффективный экзекьютор с настоящими waker'ами будет в M4b.
- `kernel_main`: демонстрация — `example_task()` делает `async_number().await` и
  печатает `async task: got 42 from an .await` на VGA.
- Новый тест `tests/async_tasks.rs`: `executor_runs_task_to_completion` — задача
  пишет в `static AtomicU32`, и после `executor.run()` значение видно (значит задача
  доведена до `Poll::Ready`). Нужна куча → тест поднимает память, как `heap_allocation`.
- async/await — стабильный, новых зависимостей не понадобилось (`core::future`,
  `core::task`, `alloc`). Проверено: `cargo test` — 8 тестов в QEMU зелёные; fmt/clippy чисто.

## 2026-06-26 — M4b: эффективный экзекьютор с настоящими waker'ами

- `sched/mod.rs`: добавлен `TaskId` (уникальный id из атомарного счётчика); `Task`
  теперь хранит свой id.
- `sched/executor.rs`: `Executor` — задачи в `BTreeMap<TaskId, Task>`, очередь id
  «разбуждённых» задач (`Arc<crossbeam_queue::ArrayQueue<TaskId>>`) и кэш waker'ов.
  Опрашивает только разбуждённые задачи; когда их нет — спит на `hlt` (`enable_and_hlt`
  атомарно делает `sti; hlt`, чтобы не проспать пробуждение). `run()` — `-> !`,
  главный цикл ядра после старта.
- `TaskWaker` реализует `alloc::task::Wake`: `wake()` кладёт `TaskId` задачи в общую
  очередь готовых (`Waker::from(Arc::new(...))`).
- Новая зависимость `crossbeam-queue` (без std, фича `alloc`) — лок-фри `ArrayQueue`.
- `main.rs`: после старта ядро запускает `Executor::run()` вместо `hlt_loop` — CPU
  спит, пока нет работы. Демо-задача `example_task` гоняется через него.
- Новый тест `executor_runs_yielding_task`: задача один раз делает `Pending` + self-wake,
  а `run_ready_tasks` доводит её до `Ready` — проверка всего пути пробуждения.
- Проверено: `cargo test` — 9 тестов в QEMU зелёные; fmt/clippy чисто. API сверены с
  исходниками `crossbeam-queue 0.3.12` (`ArrayQueue::new/push/pop/is_empty`),
  `x86_64 0.15.4` (`enable_and_hlt`) и `alloc::task::Wake`.
