# Journal — M2: Interrupts

## 2026-06-26 — M2a: IDT + breakpoint exception

- Added `src/interrupts.rs`: a global `InterruptDescriptorTable` (built lazily via
  `spin::LazyLock`, loaded with `init_idt`), with an `extern "x86-interrupt"`
  `breakpoint_handler` that prints the interrupt stack frame and returns.
- New dependency `x86_64 = "0.15"`; enabled `#![feature(abi_x86_interrupt)]`.
- `lib::init()` loads the IDT; called from both `_start`s (production and lib-test).
- Production `_start` triggers `int3` as a demo: the handler prints the frame and
  execution continues (`...survived the breakpoint`).
- Test `breakpoint_exception_returns` passes in QEMU — without a handler this would
  triple-fault and reboot the machine.
- Verified visually: QEMU screen shows `EXCEPTION: BREAKPOINT` + the decoded
  `InterruptStackFrame`, then the "survived" line.

### Note
- VGA is ASCII-only for now: non-ASCII bytes (e.g. an em dash) render as the `■`
  placeholder. Proper UTF-8 handling is a possible later refinement.

### Next (M2b)
- Double-fault handler + a GDT with a TSS and an IST (Interrupt Stack Table) stack, so
  a kernel stack overflow is caught cleanly instead of triple-faulting.

## 2026-06-26 — M2b: double fault + GDT/TSS/IST

- Added `src/gdt.rs`: a TSS holding one emergency stack in the IST
  (`DOUBLE_FAULT_IST_INDEX = 0`), and a GDT with a kernel code segment + TSS descriptor.
  `gdt::init()` loads the GDT, reloads `CS`, and loads the TSS (`ltr`). The stack address
  is taken via `&raw const STACK` (no reference to a `static mut`).
- `interrupts.rs`: added a diverging `double_fault_handler` (takes an error code), pinned
  to the IST stack via `set_stack_index`.
- `lib::init()` now runs `gdt::init()` then `interrupts::init_idt()` — order matters, the
  IDT references the IST stack from the TSS.
- Integration test `tests/stack_overflow.rs` (`harness = false`): deliberately overflows
  the stack; without the IST this would triple-fault and reboot. Its own double-fault
  handler exits QEMU with success — and it passes.

### Next (M2c)
- Hardware interrupts: initialize the 8259 **PIC**, enable interrupts, and handle the
  **timer** tick and **keyboard** input (the first real input!).

## 2026-06-26 — M2c: hardware interrupts (PIC, timer, keyboard) — M2 complete

- `interrupts.rs`: initialized the 8259 **PIC** (remapped to vectors 32..47 via
  `pic8259::ChainedPics`), added timer (vector 32) and keyboard (vector 33) handlers,
  each signalling EOI. `lib::init()` now also calls `PICS.initialize()` and `sti`
  (`interrupts::enable`).
- **Timer** handler prints a `.` per tick (~18 Hz). **Keyboard** handler reads the
  scancode from port `0x60` and decodes it with `pc-keyboard` (`PS2Keyboard`, US layout,
  scancode set 1), printing the character.
- **Deadlock fix** (promised in M1b): `vga_buffer::_print` and `serial::_print` now wrap
  the lock in `without_interrupts`, so an interrupt can't fire while we hold the writer
  lock and try to re-take it.
- New deps `pic8259 = "0.11"`, `pc-keyboard = "0.9"`.
- Note: let-chains (`if let … && let …`) need edition 2024; on 2021 we use nested `if let`.
- Verified: QEMU shows rows of timer dots, and keystrokes sent via the monitor
  (`sendkey`) appear interspersed — the kernel is now interactive. All tests still pass.

**M2 is done.** The kernel handles exceptions (breakpoint, double fault on an IST stack)
and hardware interrupts (timer, keyboard), with deadlock-safe printing. Next tier:
**M3 — memory** (frame allocator, paging, a kernel heap → `Box`/`Vec`/`String`).
