# Journal — M3: Memory

## 2026-06-26 — refactor(layout): раскладка перед M3

Перед началом M3 (когда дерево вот-вот вырастет) ввели слоистую структуру `src/`
с изоляцией арх-специфики — самой дорогой для ретрофита границы (в роадмапе
запланированы ARM/RISC-V). Подробности — в PR #9 и `docs/DECISIONS.md` (D7).

- `arch/x86_64/{gdt,interrupts}.rs` — весь CPU/платформенный код; переносимое ядро
  ходит к железу только через `arch::init()`.
- `drivers/{vga,serial}.rs` — драйверы устройств.
- Заглушки подсистем: `mm` (M3), `sched` (M4), `syscall` (M5), `fs` (M6), `net` (M8),
  `util`.
- Зафиксировали паттерны разработки: `docs/CONVENTIONS.md` (слои/HAL-шов, политика
  `unsafe`, глобальное состояние, ошибки, тесты, нейминг) и `docs/HARDENING.md`
  (backlog «второго захода»: PIC→APIC, NX/W^X, huge pages и пр.).
- Чистый рефактор: поведение не менялось, build/fmt/clippy/test зелёные.

## 2026-06-26 — M3a: доступ к таблицам страниц и трансляция адресов

- Включили фичу bootloader `map_physical_memory`: он отображает всю физическую
  память по фиксированному оффсету и кладёт его в `BootInfo::physical_memory_offset`.
  Теперь любой физический адрес (включая сами таблицы страниц) доступен ядру по
  формуле `virt = phys + offset`.
- `main.rs` перешёл с рукописного `extern "C" fn _start` на макрос `entry_point!`
  из `bootloader`: он проверяет сигнатуру `kernel_main(&'static BootInfo)` и
  безопасно прокидывает структуру с картой памяти и оффсетом.
- Новый модуль `mm/paging.rs`:
  - `active_level_4_table()` — берёт физ. адрес активной L4-таблицы из регистра
    `CR3`, прибавляет оффсет, возвращает `&mut PageTable`;
  - `init()` — оборачивает это в `OffsetPageTable` (`x86_64` 0.15), готовый
    транслятор «оффсетного» типа.
- Демонстрация в `kernel_main`: переводим три виртуальных адреса в физические
  через трейт `Translate`. Вывод (serial — отладочный канал):
  - `0xb8000` (VGA) → `Some(0xb8000)` — identity-mapped нижняя память;
  - `physical_memory_offset` → `Some(0x0)` — начало отображения физпамяти;
  - `0xdeadbeef` → `None` — ничем не отображён.
- Проверено: `cargo test` (все 4 теста в QEMU) зелёный; ядро загружается через всю
  демонстрацию без фолтов. fmt/clippy чисто.
- API сверены с docs.rs под пин-версии: `OffsetPageTable::new(&mut PageTable,
  VirtAddr)` (`unsafe`), `Cr3::read() -> (PhysFrame, Cr3Flags)`, `BootInfo` с полями
  `physical_memory_offset`/`memory_map`.
